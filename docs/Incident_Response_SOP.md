# Incident Response SOP (MVP)

Scope: security events generated by ShopSquire services and agents.

1. Detection
- Alerts: Prometheus/Alertmanager routes `security` alerts to on-call.
- Signals: `security_events` table, Grafana dashboard, Splunk search `sourcetype=shopsquire:security`.
- External: If JanuSec is configured (`JANUSEC_API_URL`, `JANUSEC_API_KEY`), review correlated triage entries.

2. Triage
- Validate alert context and recent events for the entity (tenant/user/order).
- Check `incidents` in the admin view; confirm auto-created ticket metadata.
- Severity mapping: critical → P1, high → P2, warn → P3, info → P4.

3. Containment
- If BEC suspected and DMARC fail: quarantine related messages and disable risky automations.
- If webhook spoofing: rotate webhook secret, enable stricter signature windows.
- If API key leak: revoke/rotate via provider; update stored secrets.

4. Eradication
- Patch rules or guardrails that allowed the behavior.
- Add IOCs to blocklists (domains, IPs, tokens). Confirm in Splunk.

5. Recovery
- Re-enable automations behind feature flags gradually.
- Monitor for recurrence using dashboard panels and SLO burn rates.

6. Post-incident
- Add a `decision_log` entry with evidence and actions.
- Run blameless RCA within 48h; add remediation tasks and owners.

Runbooks
- Webhook Signature Spike: rotate secret, tighten time skew, enable replay cache.
- LLM Prompt Injection: update tool allowlist, strengthen pre-checks, retrain examples.
