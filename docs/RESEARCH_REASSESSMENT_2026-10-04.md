# Research reassessment and concrete application — 4 October 2026

Primary sources were checked again for this review. These papers, lab articles and documentation describe external results, not ShopSquire results. Some are older work newly applied here; publication and revision dates are not the date of this review. No model was installed or promoted. The source evidence does not establish a model winner for this shop.

## What changes in the plan

The strongest immediate research application is **better evaluation and evidence handling**, rather than another architecture. ShopSquire already has persisted case state, a typed compiler, hybrid retrieval, bounded model execution, a graph repository and a policy-comparison simulator. Newly reproduced local gaps are identity wiring, stock-state invalidation and discarded inbound ETAs. Research does not remove those obligations.

Keep the next AI market-intelligence result read-only: explain whether to wait, expedite an existing inbound order, review an alternate supplier, or consider additional replenishment, using an ETA-aware reconciled history. An accepted 40-unit request is a commitment, not an inferred recurring demand increase. Compare actions through tested arithmetic and simulated outcomes. Model prose cannot change stock or confer approval.

## Small evaluation plan

1. Freeze a modest development/holdout split across several electronics categories and demand regimes. Reuse canonical SKU/configuration identities. Keep simulator latent demand separate from model-visible observations.
2. Include no-change, shortage, return, cancellation, delayed inbound, supplier substitution, price expiry and misleading-news scenarios. Backtests can only consume information published/available by their cutoff.
3. Compare the corrected calculator/baseline first. A probe today changed an inbound arrival from two to 367 days away without changing the current dataset or decision. No model can recover an ETA that was discarded before inference.
4. Add one extraction/retrieval improvement at a time. Measure field correctness, units, supported spans, relevance and abstention; a trusted source URL does not make every sentence relevant to a particular SKU/workload.
5. Add one forecasting challenger and ablate external signals. A beneficial oracle-like synthetic signal is only an upper-bound demonstration; test stale, noisy and false signals too.
6. Run decision and security checks through the same API/UI, with fixed fake transports. Thresholds for effect integrity, supported qualification, latency and resource use must be declared before the held-out run.

Large context windows, neural-memory architectures, recursive document analysis and broad graph infrastructure remain optional experiments. They are not substitutes for the missing caller identity, connected recovery or an ETA-aware dataset. No new architecture adoption is justified by this review alone.
