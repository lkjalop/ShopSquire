# Saved supplier draft continuity through chat

After an operator removed the buyer budget from an enquiry, ordinary chat previously regenerated the initial composition, including the budget. It also hid multiple saved enquiries, corrupted stored content and expired inventory coverage behind a fresh draft. That violated continuity even though initial preview/review/dispatch tests passed.

Chat now reads the single current saved version through the existing tenant/case/selection and inventory checks. It returns the stored version, body and content hash, with no send authority. Multiple enquiries require selection; stale coverage requires review; invalid stored JSON/content is reported unavailable. A known saved draft never silently falls back to a new composition. Before any enquiry exists, the explicitly provisional composition remains available. Editing, approval and dispatch still use their existing effect gates.

The final independent controls reproduced **nine failures in 11 cases** on the preceding committed implementation; the two controller/buyer rejection controls already passed. The repair retained those expectations and passed **129 selected tests with no failures/errors/skips** on the independent repair checkout. Ruff passed; formatting preserved the Python AST.

A separate native disposable PostgreSQL/Redis selection passed **15 controls**, including the new cross-transaction saved-version positive and expired-coverage rejection, existing concurrency/draft controls and two separately scoped privacy controls. All owned containers were removed. The extended saved-draft browser journey also passed in the larger frozen C17 working-tree candidate, including reading version 2 from buyer chat before and after reload. That browser source includes additional local WIP and is separate from independent public-cohort qualification.

The first direct-call fixture omitted an operation ID, and a later SQLite fixture failed to commit its operator write before the separate chat transaction. The native fixture initially unpacked its return incorrectly. These setup failures are retained and are not counted as reproduced product defects. The final unchanged-expectation red above uses the corrected, committed transaction setup.

Remaining limits: the browser has no general chooser for several supplier enquiries; explicit natural-language budget-disclosure amendments need a complete draft-edit contract; real provider delivery/reconciliation and deployed independent-person approval remain open. No real supplier email was sent.
